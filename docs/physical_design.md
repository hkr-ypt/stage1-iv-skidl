# Physical design as source: the routed, bipolar board of record

> **Later changes.** This note is kept as written. No copper, pad or
> placement described here has changed since. The final design audit
> ([`final_audit.md`](final_audit.md)) changed what is fitted on it: U5 is
> an **OPA547T** (the "OPA548 holes" below are its holes: same package and
> footprint); R30 dissipates up to **1.96 W** in the rail fault, not the
> 1.6 W given below; and the snubber **R38/C49 is fitted** (R38 = 100 Ω),
> not DNP.

This repository used to generate an auto-placed, **unrouted** board and keep
the board that actually gets built — placed and routed by a person in KiCad —
as a separate, hand-maintained project in `unipolar-routed/`. The two could only drift
apart. This note describes what replaced that: the routed board is now
**generated from source**, the bipolar-measurement change is applied to it as a
reasoned engineering change order (ECO), and the result is checked against the
circuit, against the original human board, and by KiCad 10's own DRC.

## Which board is which

| File | What it is | Edited by |
|---|---|---|
| `unipolar-routed/diodes.kicad_pcb` (+ `.kicad_pro`, `.kicad_sch`) | The **original, unipolar, human-placed and human-routed** board. The reference everything below is proven against. Never modified by any tool here. | nobody (reference) |
| `stage1_iv.kicad_pcb` | The **bipolar board of record**: the human placement and routing plus four ECOs (bipolar, audit corrections, final corrections, policy clearance), fully routed. Generated by `python3 main.py`. | nobody — regenerated; hand edits are detected and overwritten |
| `build/reference_reproduction.kicad_pcb` | The original board regenerated from the layout source (proof artefact, not committed). | `tools/reproduce_reference.py` |
| `build/autoplace/stage1_iv.kicad_pcb` | The old auto-placer's unrouted bootstrap board (`python3 main.py --autoplace`; not committed). Useful only for starting a *new* layout. | `generators/pcb.py` |

## Source architecture

```
blocks/*.py (SKiDL) ──────────► parts: footprints, values, fields, pad nets,
                                schematic links (generators/pcb.py::prepare_footprints)
layout/stage1_iv.layout ──────► placement, footprint-text positions, tracks,
   (captured from unipolar-routed/)      vias, zones, outline, board setup, as-built rules
layout/bipolar.eco ───────────► the bipolar change: add/remove operations,
                                each with a (reason ...)
layout/audit_corrections.eco ─► the final hardware audit corrections, applied
                                after bipolar.eco, same rules
layout/final_corrections.eco ─► the remaining corrections (U12, D7/D8/D9, F2,
                                R10, F1 move) and board-only mounting holes
layout/policy_clearance.eco ──► re-routing to the repository netclass
                                clearances, applied last
             └──► generators/routed_pcb.py ──► stage1_iv.kicad_pcb
```

Not everything is in SKiDL, deliberately. SKiDL describes connectivity; the
physical design is a different kind of fact — coordinates a person chose — and
putting 849 track coordinates into Python would be a giant hard-coded script.
The layout source is data: one item per line, sorted, so a `git diff` of a
layout change reads as the list of physical changes it is.

* **Parts come from the circuit, not the layout.** A value, net or field change
  in `blocks/*.py` reaches the routed board on the next build without touching
  `layout/`. A part the circuit has and the layout does not place (or the
  reverse) is an error, never a guess.
* **Geometry comes from the vendored footprint library**
  (`libraries/footprints`, pinned 9.0.9.1), placed exactly the way KiCad stores
  a placed footprint (`generators/footprint_xform.py`: pad angles absolute,
  text kept upright, bottom-side mirroring — verified on all 113 footprints of
  the routed board).
* **The layout holds only decisions.** Placement (side, x, y, rotation); a
  footprint text only where the designer moved it from the default; every
  track and via by net name; zone definitions (not fills — KiCad computes
  those); the outline and free silkscreen text (an ECO adds board text with
  `(add (graphic (gr_text ...)))`); the board setup verbatim; the design rules
  the board was routed to.
* **An ECO is explicit.** `(remove ITEM (reason ...))` names the exact item and
  fails if the base no longer has it, so an ECO cannot silently stop applying;
  `(add ITEM (reason ...))` adds one; `(move (footprint ...))` re-places a part.
  No operation is accepted without a reason.
* **Deterministic.** UUIDs are derived from content (UUIDv5), items are written
  in a fixed order, and the output is byte-identical run to run (CI builds
  twice and compares).

Tools:

| Tool | Role |
|---|---|
| `generators/layout.py` | the layout/ECO model, parser and writer |
| `generators/footprint_xform.py` | places a library footprint as KiCad stores it |
| `generators/routed_pcb.py` | emits the board from parts + layout + ECOs |
| `tools/capture_layout.py` | captures a routed board (and its project's rules) into a `.layout`; `--check` proves the committed capture is current |
| `tools/reproduce_reference.py` | proves the layout source reproduces the original board (below) |
| `tools/compare_boards.py` | independent semantic comparison of two boards (either KiCad schema) |
| `tools/board_geometry.py`, `tools/eco_route.py` | real-copper geometry, and a two-layer grid A* used to *design* ECO tracks at the repository's netclass clearances. Never run at build time; its output is reviewed, snapped to pad centres and existing track points, and written into the ECO with a reason |
| `validation/routed_board_check.py` | checks the board of record (below) |

## Proof: the original board regenerates from source

`python3 tools/reproduce_reference.py` (CI runs it) emits the original board
from `layout/stage1_iv.layout` plus the original board's *own* electrical
content, and compares:

| Check | Result |
|---|---|
| layout capture is current | identical to a fresh capture of `unipolar-routed/diodes.kicad_pcb` |
| parts, placement, rotation, side, pads, pad nets, values, fields, footprint graphics and texts, tracks (849), vias (94), zones (2), outline, holes, setup | identical, except 12 strings on C31/C44/C45 (below) |
| KiCad 10 DRC, the routed project as the designer left it, + schematic parity | identical: 2 `silk_edge_clearance` warnings (J3 silk over the board edge), 0 unconnected, 0 parity |
| KiCad 10 DRC, as-built rules with every check on | identical: the same 2 warnings, 0 errors, 0 unconnected |
| zone fill after KiCad refills both | identical copper: symmetric difference 0.000000 mm² on all four zone layers |
| both boards re-saved by KiCad 10, UUIDs masked | 1072 of 1075 top-level items textually identical; the 3 that differ are C31/C44/C45 |

The only differences are **not layout**: C31, C44 and C45 were added to the
routed board by hand from KiCad 10's own library, whose revision of
`C_0603_1608Metric` differs from the vendored 9.0.9.1 one in two strings
(description text, 3D-model path variable). Pads, courtyard, silk and fab
geometry are identical. The board is not byte-identical to the original
because KiCad 10 wrote the original in its 20260206 schema and the generator
writes the 20241229 schema the vendored footprints use; the re-save
comparison shows that difference is serialisation only.

## The bipolar ECO

`layout/bipolar.eco`, 25 operations; details and reasoning in
`docs/bipolar_measurement.md` §5. In summary: no part moved, no existing track
or via rerouted, outline, holes and pour definitions unchanged.

* removed: 3 AGND segments (U8 pin 5's stub — the pin leaves AGND);
* added: R32, R33 (0603, F.Cu, left of U7's inputs); 15 segments (U8 pin 4–5
  jumper 0.65 mm; U6 REF route 13.9 mm + 1 via; U7 REF route 19.7 mm; R33 and
  R32 stubs 2.1 and 1.6 mm), all 0.25 mm wide;
* silkscreen: R32/R33 designators on F.Fab; R12's designator moved beside R12
  (R32 now sits where it was printed).

Result: 115 footprints, 861 tracks (849 − 3 + 15), 95 vias (94 + 1), 2 zones.

## The audit-corrections ECO

`layout/audit_corrections.eco`, 140 operations, applied after the bipolar ECO.
The electrical reasoning is in the SKiDL blocks and in
`docs/audit_corrections.md`. Every new track was designed with
`tools/eco_route.py` against the real copper at the repository's netclass
clearances, then checked by KiCad DRC.

* **DAC reference gate (F2).** The VREF_2V5 copper inside U4's pocket is
  removed (5 segments, 1 via). U11, C46 and R35 are placed below U4, outside
  the AGND loop. New copper: DAC_VREF from U4 pin 2 to U11 D and R35, V_DACB
  from U4 pin 3 to R1 pin 1, VREF_2V5 to U11 S, +5VA to U11 VDD/C46, and the
  /SYNC pull-up R34 on the back side by U4.
* **Heartbeat pump (F2).** R36, C47, D6, C48 and R37 in a row south of U9 on
  the DGND side, with PC5 → R36 and DAC_ARM → U11 SEL across the split. That
  is a logic-level signal; only edges carry energy on it.
* **AGND stitching.** The new tracks cut the U4/C13/R31-star F.Cu fill off the
  main AGND pour, so three AGND vias stitch it to the B.Cu plane. The third, at
  (120.5, 72.5), was needed because the first two landed in a B.Cu pocket that
  the R34 route closed.
* **R30 (F3).** Re-placed at (87.75, 75.7), rotated 90°, on a DIN0411 12.7 mm
  footprint. Its courtyard is 7 mm from the R12/R13/R32/R33 divider, but only
  2.1 mm from F1's: R30 is electrically between F1 and D5/J4, and the strip
  between F1 and the J6 jack is the only room within reach. Pad 2 sits
  straight below D5 pin 1. Its FORCE+ and F1_MID tracks are rerouted at
  0.5 mm. Mount the body raised
  about 3 mm: it dissipates about 1.6 W in the rail-fault case (`blocks/protection.py`).
  *Superseded by the final-corrections ECO below: F1 moved away.*
* **Snubber (V1).** R38/C49 (0805, DNP) beside U5, from VO_RAW (0.5 mm) to
  AGND.
* **Status LED.** LED1 stays in place. Its anode pad now takes +3V3D (via, then
  B.Cu, to the +3V3D track at x = 146.75). Its cathode pad takes the R23
  copper, renamed LED_K, and its DGND stub is removed.
* **Silkscreen (F1).** `BENCH SUPPLY` with `+15V`, `-15V`, `+5V`, `GND` at
  J1's pins (J1's own designator moves to the end of the strip), and
  `FORCE+`, `FORCE-`, `SENSE+`, `SENSE-` beside J4–J7. Designators of the new
  parts go on F.SilkS where there is room and on F.Fab where there is not, as
  R32/R33 already did.

Result: 126 footprints, 889 tracks (861 − 29 + 57), 107 vias (95 − 3 + 15),
2 zones.

## The final-corrections ECO

`layout/final_corrections.eco`, 72 operations, applied after the audit ECO;
the electrical reasoning is in `docs/final_corrections.md`.

* **F1** moved to the bottom edge (90.6, 92), 14.1 mm body to body from R30
  and 22.8 mm from U5; VO_SENSE reaches it on B.Cu and F1_MID returns to R30
  pad 1 on B.Cu, both under the Kelvin runs.
* **U12** (photorelay) in F1's old place, outputs between R30 pad 2
  (FORCE_SW) and D5/J4 (FORCE+); its LED string **R39** (top) and **D7**
  (bottom) between the ±15 V runs.
* **D8** (top, beside U6) and **D9** (bottom, under the protection area):
  the dead-rail clamps, each straight across its rail to AGND.
* **R10** on the DIN0614 footprint, flat in the top band; **F2** beside J7.
  FORCE− runs J7 → F2 on F.Cu, ISENSE_HI F2 → R10 pad 1 on F.Cu, and U6 +IN
  leaves the same pad on its own B.Cu trace through TP3 (the Kelvin tap).
* **Mounting holes** H1–H3, `stage1_iv:MountingHole_3.2mm_M3_Isolated`
  (board-only footprints placed by `(board_part ...)`): NPTH, no copper, a
  4.0 mm-radius keepout on both copper layers and a 4.25 mm courtyard on both
  sides.
* Designators of the new parts on the Fab layers where silkscreen has no
  room.

## The policy-clearance ECO

`layout/policy_clearance.eco`, 293 operations, applied last. Every run the
human routing (or an earlier ECO) drew closer than its netclass allows is
removed and redrawn between the same terminals at the policy clearance:
first by `tools/eco_route.py`, then by hand in 21 areas where it found no
path. Widths are unchanged except one ADC_XTAL1 segment (0.40 → 0.25 mm, its
class width). Re-routing removed a jumper that was the only link of two F.Cu
AGND pour islands; four stitch vias to the B.Cu pour replace it. No part
moved. Of the 109 policy errors the board had before, 87 were fixed this way
and 22 were a classification error in `libraries/netclasses.py` (four
logic/supply nets in the high-impedance analog class), corrected there with
the reason (`docs/final_corrections.md` §2.3).

Result: 132 footprints + 3 mounting holes, 897 tracks, 113 vias, 2 zones.

### OPA548 holes

U5's footprint is now `stage1_iv:TO-220-7_P2.54x3.7mm_StaggerOdd_Lead3.8mm_Vertical_Drill1.2mm`,
a project footprint generated by `tools/vendor_footprints.py` from KiCad's
TO-220-7: the same pads and positions with the drill widened from 1.1 to
1.2 mm. Placement and copper are unchanged; the pads' annular ring shrinks by
0.05 mm per side and DRC passes.

### Mounting holes and bottom-side test points: decisions

* **Three mounting holes, not four.** *(Revised; the audit round added
  none.)* The corners are taken by J7, J5, J1 and J3, but three positions
  near the edges have room for an isolated M3 with its keepout: H1 (87.7,
  37.5), H2 (122.2, 88.2), H3 (157.7, 89.2). The top-right quadrant does not
  (at most 2.7 mm free radius). The front edge is carried by the panel jacks;
  see `docs/final_corrections.md` §2.4.
* **The bottom-side test points stay.** Moving them is a re-placement for no
  electrical gain, and on a bench board they are reached with a probe from
  below. The bring-up checklist says so.

## Design rules and what DRC says

Two rule sets matter, and the board is reported against both:

* **As-built** — what the board was routed to: the routed project's single
  `Default` netclass (0.20 mm clearance, 0.20 mm track, 0.6/0.3 mm via) and its
  board minimums, captured into the layout as `(rules ...)`.
* **Repository policy** — `libraries/netclasses.py`, written by
  `tools/gen_project_config.py` into `stage1_iv.kicad_pro`/`.kicad_dru`: nine
  classes with 0.25 mm for sense nets and 0.30 mm for the ±15 V rails.

One finding from this work: **the routed project had clearance checking turned
off** (`"clearance": "ignore"` in `unipolar-routed/diodes.kicad_pro`), so the original
board's clean DRC never included clearance. Turned on, under its own 0.20 mm
class, the only errors are 40 pad pairs *inside* U2, U4 (VSSOP-8) and J3
(USB-C), whose 0.15 mm pad gaps belong to the packages; the repository's
scoped rules (`stage1_iv.kicad_dru`) narrow exactly those. With them, the
original human routing has **0 clearance errors** — so the as-built check below
runs with every KiCad check on and does not inherit the `ignore`.

KiCad 10.0.7, `kicad-cli pcb drc --refill-zones --all-track-errors
--schematic-parity`, on `stage1_iv.kicad_pcb` with all four ECOs:

| Rule set | Errors | Warnings | Unconnected | Parity | The original under the same rules |
|---|---|---|---|---|---|
| as-built + scoped intra-footprint rules, every check on | **0** | 2 (`silk_edge_clearance`, J3) | **0** | — | 0 errors, the same 2 warnings |
| repository netclass policy (`stage1_iv.kicad_pro`) | **0** | 2 (same) | **0** | **0** | 92 clearance errors (its 0.20 mm routing) |

History of the policy count on the board of record: 116 on the original →
114 (bipolar ECO) → 109 (audit ECO) → 0 (final corrections:
22 resolved by correcting four nets' class, 87 re-routed by
`layout/policy_clearance.eco`; `docs/final_corrections.md` §2.3).

So: **the board is fully routed and DRC-clean under the rules it was routed
to and under the repository's netclass policy.** For reference, IPC-2221B
(B2, external, uncoated) asks 0.1 mm up to 30 V; the policy's 0.25–0.30 mm is
margin for leakage and the ±15 V rails, not a safety minimum.

`validation/routed_board_check.py` enforces all of this (and `main.py` runs it):

1. **Source and circuit** — the board is byte-for-byte what circuit + layout +
   ECO generate (so a hand edit fails); board parity with the circuit;
   schematic linkage; Update PCB from Schematic would change nothing (and that
   model's calibration still matches real KiCad output); board schema;
   netclass coverage; fab conformance; rules file parses; rule satisfiability.
2. **Placement heuristics relative to the original** — the repository's
   courtyard, edge, ground-split, hole-spacing and silkscreen checks were
   written for the auto-placer and are coarser than KiCad (the courtyard check
   compares bounding boxes on both sides at once, so an SMD part on the back
   under a DIP "overlaps" it). On the human layout they report 140 findings,
   every one also on the original. The check fails on any finding the
   original does not have — anything the ECO introduced.
3. **KiCad DRC** — both rule sets, as above. Fails on any error under
   either rule set (pre-existing on the original or not), any unconnected
   item under either zone fill, any parity problem, and any warning the
   original does not have (matched by what and where — item kind, layer,
   position, measured value — not by net, since the ECO renames a few pads'
   nets). Without KiCad 10 this layer is reported
   **NOT RUN**, never passed.

## Changing the board

* **Values, nets, fields** — edit `blocks/*.py`; rebuild. The layout is
  untouched; `routed_board_check` will fail if a new net or pad needs copper
  (unconnected items) or a new part needs a placement (the generator refuses).
* **A physical change** — add operations to an ECO (a new `layout/*.eco`,
  listed in `generators/routed_pcb.py::ECOS`), each with its reason. Design new
  tracks against the real copper (`tools/eco_route.py`), snap them to pad
  centres and existing track points, and let `routed_board_check` (KiCad DRC)
  judge them.
* **Larger rework in KiCad** — open `stage1_iv.kicad_pcb`, work, save, then
  capture it as a *new* base layout, e.g. `python3 tools/capture_layout.py
  stage1_iv.kicad_pcb layout/stage1_iv_r2.layout --project
  unipolar-routed/diodes.kicad_pro` (the project that holds the as-built rules), point
  `BASE_LAYOUT` in `generators/routed_pcb.py` at it and empty `ECOS` — the
  ECOs are part of the new base. Keep `layout/stage1_iv.layout` as the
  capture of `unipolar-routed/`; `tools/reproduce_reference.py` proves it. Do not leave
  hand edits in `stage1_iv.kicad_pcb`: the next build overwrites them, and
  `generated_from_source` fails until they are captured.
* **Never** edit `unipolar-routed/`. It is the unipolar reference the reproduction is
  proven against.

## Not verified

* No KiCad ERC/DRC was run on a machine other than this CI configuration
  (KiCad 10.0.6, and 10.0.7 for the audit corrections, locally; CI installs
  KiCad 10 from the KiCad PPA).
* No fabrication-house DFM check, no Gerber review by a person, no SPICE or
  bench measurement of the bipolar chain.
* Zone fills are derived by KiCad at DRC/plot time; the committed board holds
  the pour definitions without fill (open it and press B, or plot with
  `kicad-cli pcb export gerbers --check-zones`).
