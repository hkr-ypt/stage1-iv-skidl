# PCB generation and board setup

This document covers Prompt 3: how `stage1_iv.kicad_pcb` is produced, where
every board-setup number comes from, and — plainly — what state the board is
actually in.

## The headline, first

**The board is not routed, DRC has not been run in this environment, and
nothing in this repository claims a DRC pass.**

| | |
|---|---|
| Board | 114.22 × 96.48 mm, 2 layers, 1.6 mm FR-4 |
| Footprints placed | 110 (+ 4 mounting holes) |
| Nets | 66, every one in an explicit netclass |
| Tracks | **0** |
| Connections still to route | **241** (73 of which the ground pours cover) |
| Autorouted | **no** |
| `kicad-cli pcb drc` result | **not run** — see §"Why DRC has not been run here" |

## What was generated, and from what

Nothing was clicked in the KiCad GUI. Board setup lives in the project file,
which `tools/gen_project_config.py --check` regenerates and compares — so a
GUI edit to clearances, track widths, netclasses or via sizes fails CI. Change
the source.

## Assumed fabrication capability

Stated in full in [`FAB_CONSTRAINTS.md`](FAB_CONSTRAINTS.md), and it is an
**assumption**: no fabricator has been chosen. The load-bearing rows:

| ID | Parameter | Value |
|---|---|---|
| F1 | Layers | 2 |
| F2 | Copper | 1 oz outer |
| F3 | Min track | 0.15 mm |
| F4 | Min clearance | 0.15 mm |
| F5 | Min drill | 0.30 mm |
| F6 | Min annular ring | 0.15 mm |
| F7 | Min via | 0.30 mm drill / 0.60 mm pad |
| F8 | Copper to edge | 0.50 mm |
| F12 | Thickness | 1.6 mm |

`libraries/netclasses.py::check_against_fab()` refuses to emit a board whose
netclasses ask for anything below these, so a capability downgrade cannot
quietly produce an unbuildable board. `tools/test_guard_fails.sh` case 12
injects a 0.10 mm track width and shows the build failing.

## Global clearance

`GLOBAL_MIN_CLEARANCE = 0.13 mm`, and it is a **DRC floor, not a routing
target**.

It is derived, in one step, from a measurement:

```
GLOBAL_MIN_CLEARANCE = INTRINSIC_MIN_PAD_GAP (0.15) − GLOBAL_CLEARANCE_MARGIN (0.02)
```

`INTRINSIC_MIN_PAD_GAP` is not asserted. `tools/measure_pad_gaps.py` opens
every footprint file the design uses and computes the edge-to-edge distance
between every pair of pads on a shared copper layer:

```
$ python3 tools/measure_pad_gaps.py
  TIGHTEST: 0.150 mm in Connector_USB:USB_C_Receptacle_GCT_USB4085
            (pads A5/A6, used by J3)
```

| Footprint | Used by | Pitch | Measured pad gap |
|---|---|---|---|
| `Connector_USB:USB_C_Receptacle_GCT_USB4085` | J3 | 0.85 mm | 0.150 mm |
| `Package_SO:VSSOP-8_3x3mm_P0.65mm` | U2, U4 | 0.65 mm | 0.150 mm |
| `Package_QFP:LQFP-64_10x10mm_P0.5mm` | U9 | 0.50 mm | 0.200 mm |

That 0.150 mm is a property of the *parts*. No routing decision can widen it.
A global minimum clearance above it would produce clearance violations between
two pads of the same footprint — violations that are literally unfixable,
because neither pad can move.

The 0.02 mm margin exists because KiCad evaluates roundrect and oval pads
against their true outline while `measure_pad_gaps.py` uses the bounding box
(which *understates* the gap). The margin keeps a pad pair that measures
exactly 0.150 mm from landing marginally under the limit.

CI re-measures on every run and fails if the constant and the footprint files
disagree, so this cannot rot.

Nothing is routed at 0.13 mm. The tightest clearance any net actually uses is
0.20 mm, above the F4 fab floor; the unused `Default` class sits at F4 itself.

## Netclasses

Every one of the 66 nets is in exactly one class. **There is no default
class**: `classify()` raises `UnclassifiedNet` naming the offenders, so a net
added without a decision fails the build rather than inheriting someone else's
clearance. `tools/test_guard_fails.sh` case 9 demonstrates it.

| Class | Nets | Clearance | Track | Via (pad/drill) | Why this number |
|---|---:|---:|---:|---|---|
| `POWER_HV` | 2 | 0.30 | 0.50 | 0.80 / 0.40 | 2× F4 for the 30 V rail-to-rail between `+15VA` and `-15VA` (see below) |
| `POWER_LV` | 5 | 0.20 | 0.40 | 0.70 / 0.35 | F4 + margin; 0.40 mm at 1 oz carries ≈1.1 A at 10 °C rise (IPC-2152), covering U1's full 800 mA rating |
| `GROUND` | 2 | 0.20 | 0.40 | 0.70 / 0.35 | returns carry the rail currents; both nets are poured, so this applies to stitching and the R31 star link |
| `FORCE` | 5 | 0.25 | 0.50 | 0.80 / 0.40 | ±11 V compliance; track sized for the **fault** case (F1 holds 100 mA, D5 conducts), not the 49 mA operating current |
| `SENSE` | 8 | 0.25 | 0.25 | 0.60 / 0.30 | high-Z precision analog; current negligible, clearance buys surface-leakage margin around the Kelvin and reference nodes |
| `DIGITAL` | 15 | 0.20 | 0.25 | 0.60 / 0.30 | SPI/SWD, nothing impedance-controlled; 0.25 mm is the density compromise for escaping the LQFP-64 and SSOP-28 |
| `USB` | 6 | 0.20 | 0.38 | 0.60 / 0.30 | USB 2.0 FS pair, 0.38/0.20 mm — a known 2-layer compromise, see below |
| `LOCAL_ANALOG` | 23 | 0.25 | 0.25 | 0.60 / 0.30 | block-local analog nodes; same character as `SENSE`, kept separate so `SENSE` can be tightened later |

The full derivation text for each class is in `libraries/netclasses.py` — it is
not decoration, `validation/drc_check.py` and this table both come from it.

### The ±15 V rails

IPC-2221B Table 6-1 (external conductors, uncoated, B1, <3050 m) for 16–30 V DC
or AC peak gives **0.13 mm**. That is *below* the fab floor (F4 = 0.15 mm), so
IPC is **not** the binding constraint at these voltages — the process is.

`POWER_HV`'s 0.30 mm is therefore **margin, not compliance**: 2× the fab floor,
chosen to keep the ±15 V nets clear of adjacent low-voltage copper and of each
other under solder-mask and assembly-residue variation. It was not arrived at
by widening until DRC went quiet — nothing in this repository was.

### The USB pair — a stated compromise

On 1.6 mm FR-4 with 2 layers, the reference plane for a top-layer pair is
~1.5 mm away. No sane trace geometry reaches 90 Ω there; 0.38 mm/0.20 mm
edge-coupled lands around 100–110 Ω. This is accepted at full speed
(12 Mbit/s) over the ~30 mm run from J3 to U9, and it is a **consequence of
the 2-layer choice (F1)**, recorded rather than hidden. If the design ever
needs high speed, F1 becomes 4 layers and this class is recomputed.

## The ground split

AGND and DGND are separate pours, joined at exactly one point.

```
            x = 38.02 mm
                 │
   ┌─────────────┼─────────────────────────────┐
   │   AGND pour │ │   DGND pour               │
   │             │ │                           │
   │  dac_sweep  │ │   power    mcu            │
   │  out_buffer │R31│   adc                   │
   │  curr_sense │U8 │                         │
   │  volt_sense │ │                           │
   │  protection │ │                           │
   └─────────────┼─┼───────────────────────────┘
                 └─┴── 2.0 mm gap, straddle lane
```

* Analog blocks (`dac_sweep`, `output_buffer`, `current_sense`,
  `voltage_sense`, `protection`) sit left of the split; `mcu` sits right;
  `power` and `adc` sit right of the lane as the split blocks.
* The boundary is **not chosen by the zone code**. `generators/pcb.py` finds
  every part that bonds to both ground nets *by reading the circuit*, reserves
  a vertical "straddle lane" for them, and the zones are then poured either
  side of wherever that lane landed. The copper split and the parts that cross
  it cannot drift apart.
* **Two parts bond both grounds, and both are deliberate:**
  * **R31** — the star resistor, the single intended DC connection between the
    systems.
  * **U8 (ADS1256)** — the die genuinely has separate AGND and DGND pins.
    Bonding each to its own pour is what the datasheet asks for; it is not a
    second bridge. `validation/assertions.py::a_star_ground` has always said
    so, and `validation/drc_check.py` now enforces the layout consequence.
* `generators/pcb.py::_split_offset` refuses to place a straddling part whose
  AGND pads are not all to the left of its DGND pads — a wrongly oriented part
  fails the build instead of being placed with digital return current under the
  analog pour. (At rotation 0 the SSOP-28 puts pins 1–14 on the left: AGND on
  pins 2/3/5, DGND on pin 17. The convention and the pinout agree, which is
  checked, not assumed.)

`validation/drc_check.py::check_ground_split` enforces, on the emitted file:

1. one zone per ground net, polygons not intersecting;
2. every ground-bridging part straddles the boundary, each ground pin over its
   own pour;
3. R31 is one of them;
4. no track on a ground net crosses the boundary (there are no tracks yet; the
   check is there for when there are).

**It demonstrably fails.** `tools/test_guard_fails.sh` case 10 patches the
generator so R31 is no longer treated as a bridge; it lands in its block, and:

```
[CAUGHT] R31 no longer straddles the AGND/DGND split
         validation/drc_check.py=1, main.py=1
         - ground_split: R31 does not straddle the AGND/DGND boundary at
           x=38.020: pad 1 (AGND) at x=52.688 is over the DGND pour.
```

## Board outline, origin and mounting holes

* **Origin** is the KiCad page origin; the placement starts at (0, 0) and the
  outline extends negative by the edge margin. The board rectangle is
  (−8.5, −8.5) to (105.72, 87.98) mm.
* **Outline** is a rectangle on `Edge.Cuts`, sized from the *actual* placement
  extents plus `F8 + mounting-hole inset + mounting-hole pad/2`. It is not a
  guessed size: change a part and the board resizes.
* **Column widths are derived, then relaxed.** The starting widths are
  proportional to the courtyard area each column must hold; the packer is then
  *measured* and the widths rescaled until the three columns finish at
  comparable heights. That is why the board is 114 × 96 mm and not the
  270 × 74 mm ribbon a fixed column width produced. The relaxation is
  deterministic — same circuit, same board, verified in CI by building twice
  and diffing.
* **4 M3 mounting holes**, 3.2 mm drill / 6.0 mm pad, inset 5.5 mm from each
  corner (F8 + 5.0 mm).
* **Edge clearance** F8 = 0.5 mm, checked against every courtyard by
  `check_edge_clearance`.

## Placement

Grouped by the `skidl_block` attribute `main.py` stamps on every part, so
sheet membership and board region agree. Within a block, parts are shelf-packed
by courtyard size; decoupling capacitors are pulled to sit immediately after
the IC they decouple.

What the placement *guarantees*: no overlapping courtyards, block coherence,
analog/digital separation matching the pours, decoupling adjacency. What it is
**not**: an optimised layout. It is a sane starting point for manual routing.

## Why DRC has not been run here

`kicad-cli pcb drc` first shipped in **KiCad 8**. The newest KiCad installable
in this environment is **7.0.11**, whose `kicad-cli pcb` offers only `export`:

```
$ kicad-cli version
7.0.11
$ kicad-cli pcb --help
Usage: pcb [-h] {export}
```

KiCad 8/9 AppImages are not reachable through this environment's egress proxy.
So:

* `validation/drc_check.py` reports `kicad_drc: SKIPPED` with that reason, and
  prints, in as many words, *"DRC WAS NOT RUN. This is not a pass."*
* CI runs the same script; on a runner with KiCad 8+ it runs real DRC
  automatically, with no change to the repository.
* The board **is** validated against the real tool as far as this environment
  allows: `tools/check_kicad_loads.py` hands `stage1_iv.kicad_pcb` to
  `kicad-cli pcb export svg` and fails if KiCad cannot read it. That check
  exists because the previous prompt's symbol-library bug was exactly this
  shape — a file this project's own parser accepted and KiCad rejected.

The board is emitted in the **KiCad 7 board schema** (`version 20221018`) for
the same reason: it is the newest schema a tool here can actually parse.
KiCad 8 and 9 migrate v7 boards on load. The installed footprints are KiCad 9
files, so `generators/pcb.py::_convert` rewrites each into v7 syntax on the way
in — `(uuid)`→`(tstamp)`, `(hide yes)`→bare `hide`, `(fill yes|no)`→
`(fill solid|none)`, `(remove_unused_layers no)` dropped,
`(property "Reference" …)`→`(fp_text reference …)`.

## What is left: routing

241 connections. The ground pours cover 73 of them once filled, leaving **168**
to draw by hand. In suggested order:

| # | Group | Connections | Why first |
|---|---:|---|---|
| 1 | `GROUND` stitching | (73 via pours) | Fill both zones, add stitching vias along each pour. Everything else references these. |
| 2 | `POWER_HV` `+15VA`, `-15VA` | 27 | Widest tracks, least routable later. Feed U5 first, then U6/U7. |
| 3 | `POWER_LV` `+3V3D`, `+5VA`, `+5V_RAW`, `VDDA`, `VBUS` | 42 | `+3V3D` alone is 21 connections across the MCU; get it down before signals. |
| 4 | `FORCE` | 12 | The DUT drive path U5→R9→F1→R30→D5→J4. Short and direct; it carries fault current. |
| 5 | `SENSE` | 23 | The Kelvin pair and `VREF_2V5`. Route as a tight pair, away from digital, entirely over the AGND pour. |
| 6 | `LOCAL_ANALOG` | 35 | Block-local; short by construction once the blocks are placed. |
| 7 | `USB` | 8 | `USB_DP`/`USB_DM` as a matched pair, 0.38/0.20 mm, over unbroken DGND. |
| 8 | `DIGITAL` | 21 | Last: most tolerant of detours, and SPI2 must not cross the analog pour. |

Constraints the router (human) must honour, all enforced afterwards by
`validation/drc_check.py`:

* No track on `AGND` or `DGND` may cross x = 38.02 mm. The only DC path
  between the systems is R31.
* No digital track should run over the AGND pour; prefer routing it on the
  DGND side or on the opposite layer with a DGND return beneath.
* `SENSE+`/`SENSE-` are a Kelvin pair — route them together, and do not let
  `FORCE` current share their return.

## Regenerating

```sh
python3 main.py                      # netlist + schematic + board + all checks
python3 main.py --pcb-only           # just the board
python3 tools/gen_project_config.py  # board setup from libraries/netclasses.py
python3 validation/drc_check.py      # board checks + real DRC where available
python3 tools/measure_pad_gaps.py    # re-measure the intrinsic pad gaps
python3 tools/check_kicad_loads.py   # KiCad itself reads the emitted files
tools/test_guard_fails.sh            # prove the board checks fail on real defects
```

## What was deliberately not done

* **No autorouting.** Not attempted, not wanted here.
* **No DRC rule suppressed or excluded.** `stage1_iv.kicad_pro` contains no
  `rule_severities` section, in either the board or the ERC half, and
  `tools/gen_project_config.py --check` fails if one appears.
* **No clearance relaxed below fabrication capability.** The one value below
  F4 is the *global DRC floor*, and it is below F4 because two standard
  footprints physically are — with the derivation above and a CI check that
  re-measures it.
* **No claim that DRC passes.** It has not been run.
